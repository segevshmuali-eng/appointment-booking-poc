# מערכת ניהול תורים מודולרית (הוכחת היתכנות - POC)
מופעלת באמצעות מנוע אוטומציות n8n

---

## 📌 מבנה המערכת והאפליקציה

מערכת זו נבנתה כבסיס מודולרי גמיש שנועד לשרת מגוון עסקים רחב (קליניקות לרפואה משלימה, ספא, מספרות, מכוני יופי, סטודיו לאימונים ועוד). 

### 1. החלפת תחום עסק תוך דקה
כל הגדרות העסק (שם, תיאור, שירותים, תמונות, שעות, צבעים) מנוהלות בקובץ יחיד:
`app/config.js`
כדי להתאים את האפליקציה לכל לקוח חדש, משנים רק את הערכים בקובץ זה ללא צורך לגעת בקוד הליבה.

### 2. מאפייני האפליקציה (UX/UI)
- **סגנון פתוח ושלווה:** עיצוב בגווני מרווה, מנטה וזהוב חם, טיפוגרפיה נקייה ומרווחת ברוח הוליסטית.
- **פירוט שירותים מעמיק:** כל טיפול מוצג עם פירוט מובנה בן 3 משפטים (מקור הטיפול, קהל היעד, התועלת המרכזית).
- **גלריית קליניקה:** חלל הטיפולים, עמדות הרגיעה והאווירה הטיפולית.
- **מעבר כפול לקביעת תורים:**
  - **נגלה:** כפתור מרחף קבוע `תיאום טיפול מרגיע` שמלווה את המשתמש בכל גלילה.
  - **נסתר:** לחיצה על כותרת כל שירות מובילה ישירות ליומן ומסמנת את הטיפול הנבחר.
- **יומן ושעות בדידות:** לוח שנה לועזי המציג שעות פנויות עגולות (`16:00` ולא טווחים) וגולל אוטומטית (UX) לשלב בחירת השירות.
- **סיווג משתמש בהורדה / כניסה:**
  - **לקוח חד-פעמי:** גישה מיידית לדף הבית כאורח.
  - **לקוח קבוע:** טופס רישום מהיר עם שמירת כרטיס אשראי מאובטח (Tokenization) לחיוב עתידי בלחיצה.
- **מניעת חיוב שגוי:** התראה קופצת בתחילת התור המחייבת את הלקוח לאשר את קיום הטיפול לפני משיכת הכספים.

## ⚙️ חמש אוטומציות ה-n8n המחוברות בענן

1. **ניהול תשלומים ותזכורות כל 5 ימים (`1_payment_reminders_every_5_days.json`):**
   - דוגם את טבלת גוגל שיטס כל 5 ימים.
   - מסנן לקוחות ששדה `סטטוס` שלהם אינו `PAY` וחלפו 5 ימים ממועד התור.
   - שולח הודעת תזכורת לטלפון הלקוח עם פרטי השירות שקיבל.

2. **הפקת חשבוניות וסיום עבודה (`2_invoice_generation_green_invoice.json`):**
   - דוגם רשומות בסטטוס `PAY`.
   - מתחבר אוטומטית ל-API של מורנינג (`POST https://api.greeninvoice.co.il/api/v1/account/token`) באמצעות מפתחות ה-API של בעל העסק.
   - מפיק קבלה דיגיטלית (`POST https://api.greeninvoice.co.il/api/v1/documents`) הנשלחת ישירות למייל הלקוח.
   - מעדכן את הסטטוס בגוגל שיטס ל-`FINISH`.

3. **סנכרון יומן גוגל בזמן אמת (`3_calendar_sync_realtime.json`):**
   - מופעל בוובהוק בלייב בכל פעם שלקוח בוחר תאריך בלוח השנה באפליקציה.
   - דוגם את יומן גוגל של בעל העסק, מזהה שעות חסומות באותו יום לפי שעון ישראל (`Asia/Jerusalem`), ומחזיר שעות פנויות בלבד ללא שום עיכוב.

4. **קליטת תורים מהאפליקציה ורישום בטבלה (`4_booking_intake_google_sheets.json`):**
   - וובהוק המקבל את כל פרטי ההזמנה מיד עם לחיצה על אישור התור באפליקציה.
   - מזין שורה חדשה בטבלת גוגל שיטס עם פרטי הלקוח, מועד התור, מחיר הטיפול, מזהה טוקן של הכרטיס וסטטוס תשלום ממתין.

5. **סליקת משולם ועדכון סטטוס תשלום אוטומטי (`5_meshulam_payment_gateway_and_ipn.json`):**
   - **מסלול א' (חיוב טוקן לקוח קבוע):** כאשר התור מתקיים והלקוח מאשר את קיומו, האפליקציה שולחת קריאה לוובהוק שמחייב את הכרטיס דרך שרתי משולם. עם אישור החיוב, הסטטוס בטבלה מעודכן מידית ל-`PAY`.
   - **מסלול ב' (תשלום מהיר ב-bit / דף סליקה):** כאשר לקוח משלם ב-bit, משולם שולחת התראת וובהוק (IPN). המערכת מאתרת את שורת הלקוח בטבלה ומעדכנת אותה ל-`PAY`.

## 💡 איך המערכת יודעת שהלקוח שילם (סגירת מעגל התקשורת)

השאלה המרכזית באוטומציה היא: **כיצד מנוע ה-n8n יודע לעדכן את השורה בטבלה ל-PAY?**

1. **בתשלום לקוח קבוע (טוקן אשראי):**
   - הלקוח לוחץ על אישור קיום התור באפליקציה.
   - נשלחת בקשה ל-n8n עם מזהה הטוקן המוצפן.
   - מנוע ה-n8n פונה ל-API של משולם ומקבל תשובה מיידית: `status: 1` ומספר אסמכתא.
   - באותו שבריר שנייה, n8n מעדכנת את עמודת `סטטוס` בטבלת גוגל שיטס ל-`PAY`.

2. **בתשלום מיידי או דרך אפליקציית bit:**
   - הלקוח משלם דרך שער הסליקה של משולם.
   - שרתי משולם שולחים התראה חיה (Webhook IPN) ישירות לכתובת ה-n8n שלנו עם מספר הטלפון והסכום ששולם.
   - n8n מאתרת את השורה של הלקוח בטבלת `תשלומים ` ומעדכנת את הסטטוס ל-`PAY`.

ברגע שהסטטוס עודכן ל-`PAY`, מופעל מיד תהליך הפקת החשבונית והקבלה שנשלחת למייל הלקוח, והסטטוס משתנה ל-`FINISH`.

## 📋 מדריך מעשי: רשימת החיבורים הטכניים לכל לקוח חדש

כאשר מגיע אליך בעל עסק חדש, אלו 5 הפעולות הטכניות לחיבורו למערכת:

### 1. יומן גוגל (סנכרון זמינות תורים בלייב)
- **מה לבקש מהלקוח:** את כתובת הג'ימייל העסקית שבה הוא מנהל את הפגישות שלו.
- **מה מגדירים:** באוטומציה מספר 3 (`realtime-calendar-sync`), בצומת יומן גוגל, בוחרים או מקלידים את כתובת המייל שלו.
- **תוצאה:** כל אירוע או חסימה שבעל העסק רושם ביומן בטלפון חוסמים מיד את השעה באפליקציה.

### 2. טבלת גוגל שיטס (מאגר תורים ותשלומים)
- **מה לבקש מהלקוח:** לפתוח קובץ גוגל שיטס חדש (או לפתוח עבורו) עם שתי לשוניות:
  - לשונית `תשלומים ותורים`: עמודות `שם מלא`, `מייל`, `טלפון `, `תאריך `, `סכום`, `סטטוס`.
  - לשונית `שעות פנויות`: עמודות `תאריך`, `שעות פנויות`, `עודכן לאחרונה`.
- **מה מגדירים:** באוטומציות 1, 2, 4 ו-5 בוחרים את הטבלה החדשה שנוצרה.
- **תוצאה:** כל תור נרשם אוטומטית בטבלה עם תמונת מצב חיה של התשלומים.

### 3. סליקת משולם (תשלומים, טוקנים ו-bit)
- **מה לבקש מהלקוח:** שלושה נתונים מתוך ממשק משולם (תחת הגדרות מפתחים / API):
  1. קוד דף סליקה (`pageCode`)
  2. מזהה משתמש (`userId`)
  3. מפתח API (`apiKey`)
- **מה מגדירים:**
  - באוטומציה מספר 5 (`5_meshulam_payment_gateway_and_ipn.json`), בצומת `קריאת חיוב טוקן מול שרתי משולם`, מדביקים את שלושת הנתונים.
  - בקובץ `app/config.js` מזינים את שלושת הנתונים תחת אובייקט `meshulam`.
- **תוצאה:** חיוב אוטומטי בכרטיסי לקוחות קבועים וסליקת bit בלייב.

### 4. מערכת החשבוניות (מורנינג / חשבונית ירוקה או כל תוכנה אחרת)
- **מה לבקש מהלקוח:** שני מפתחות מתוך חשבון מורנינג שלו (תחת הגדרות -> ממשקי תכנות / API): מזהה מפתח (`Key`) ומפתח סודי (`Secret`).
- **מה מגדירים:** באוטומציה מספר 2, בצומת `התחברות למורנינג והזנת מפתחות API`, מדביקים את שני המפתחות ב-JSON ושומרים.
- **תוצאה:** הפקה אוטומטית של קבלה דיגיטלית חתומה במייל הלקוח ברגע שהסטטוס הפך ל-`PAY`.

### 5. התאמת האפליקציה למותג העסק (תוך 2 דקות)
- **מה לבקש מהלקוח:** שם העסק, לוגו, תמונות, שמות הטיפולים או השירותים ומחיריהם.
- **מה מגדירים:** פותחים את `app/config.js` ומעדכנים את שדות הטקסט, התמונות והמחירים.
- **תוצאה:** האפליקציה מציגה מיד את המיתוג, הטיפולים והמחירים המדויקים של העסק.
